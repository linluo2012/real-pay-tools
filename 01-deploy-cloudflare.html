第 1 步 · 进入 Cloudflare Pages 创建页

1
登录 dash.cloudflare.com。
2
左侧菜单点 Workers & Pages（新版界面可能藏在 Compute & AI 下面）。
3
点右上角蓝色 Create application（创建应用程序）。
⚠️ 这里有个最常见的坑 页面会出现一个大白框写着「Connect GitHub」之类。不要点它——那是创建 Worker 的入口， 点进去会走错路，部署出来的东西不是静态站。

正确做法：往下找一行小字链接，写着 「Looking to deploy Pages? Get started」（想部署 Pages？开始使用），点它。
或者：直接点 Pages 标签 → Import an existing Git repository（导入现有 Git 仓库）。

第 2 步 · 连接 GitHub 仓库（含私有仓库授权）

1
点 Connect to Git / GitHub，会跳到 GitHub 授权页，点 Authorize Cloudflare Pages。
2
回到 Cloudflare，在仓库列表里找 real-pay-tools。
如果列表里找不到 real-pay-tools（私有仓库必现）
补
点页面上那行小字：「去 GitHub 上为 Cloudflare Pages 应用配置仓库访问权限」 （英文类似 "Configure repository access on GitHub"）。
补
跳到 GitHub 的 Applications 设置页 → 找到 Cloudflare Pages → 点 Configure。
补
在 Repository access 区域选 Only select repositories（仅选择仓库）， 下拉里勾选 real-pay-tools → 点 Save。
补
回到 Cloudflare 那个页面，刷新一下浏览器，仓库就出现了。
3
选中 real-pay-tools → 点 Begin setup（开始设置）。

第 3 步 · 填构建配置（照抄这张表）

字段填什么
Project namereal-pay-tools（会生成 real-pay-tools.pages.dev）
Production branchmain
Framework presetNone（无框架，千万别选别的）
Build commandpython3 build.py --build
Build output directorydist
关于构建命令 --build 这个参数会让脚本输出到 dist/；不加参数的话是输出到本地 site/ 供预览用。云端必须用带 --build 的版本。

OG 分享图（12 张 PNG）已经提交进仓库了，云端构建不需要装 Pillow，所以不会失败。

可选：设置环境变量

点开 Environment variables，加一条，用来确保域名绝对正确：

SITE_DOMAIN = career.linwt.top

不加也行——脚本会读仓库里的 domain.txt，里面写的就是 career.linwt.top。

⚠️ 找不到 Build output directory？（第一站踩过同样的坑）

原因：Cloudflare 新版界面在检测不到框架时会简化表单， 这个字段被折叠隐藏了。

解决：把 Framework preset 选成 None， 该字段就会显现出来。（注意：是显式点选 None，不是留空）

还不行？用兜底方案：先照默认完成创建， 然后进项目 → Settings → Builds & deployments → Edit configuration（编辑配置），在里面补填 build command 和 output directory，保存后重新部署即可。创建完之后随时都能改，不用推倒重来。

4
点 Save and Deploy（保存并部署）。

第一次构建大约 1–2 分钟。构建日志可以实时看，如果失败会在日志里写明原因。

第 4 步 · 绑定自定义域名

1
部署成功后，进入项目 → Custom domains 标签 → Set up a custom domain。
2
输入 career.linwt.top → 继续。
3
因为 linwt.top 的 DNS 本来就托管在 Cloudflare（第一站用的也是它）， Cloudflare 会自动添加那条 CNAME 记录，不用你手动去 DNS 页面加。点确认即可。
4
等 SSL 证书签发，通常几分钟，最长不超过几小时。状态变成 Active 就能访问了。
⚠️ 注意：这会动到 linwt.top 的 DNS 虽然只是新增一条 career 的 CNAME，不会影响第一站 linwt.top 和 www 的现有记录，但因为是在同一个域名下操作，建议加完之后顺手去 DNS 页面看一眼，确认第一站那几条记录原封不动。两个站是各自独立的 Pages 项目， 一个出问题不会影响另一个。

第一站踩过的三个坑（第二站已提前避开两个）

现象根因解决办法
向导页找不到 Build output directory 新版界面检测不到框架时简化表单，字段被折叠 Framework preset 显式选 None；或用上面的兜底方案（创建后在 Settings 里改）
构建报 domain: example.com 残留占位域名 环境变量 SITE_DOMAIN 没注入 第二站已避开：仓库根目录有 domain.txt（内容 career.linwt.top）， build.py 直接读文件，不依赖后台配置。已实测：不带任何环境变量模拟云端构建，域名读取正确
Missing entry-point to Worker script，构建成功但部署失败 仓库里有 wrangler.toml，Cloudflare 把 Pages 误判成 Workers 项目 第二站已避开：已确认仓库内没有 wrangler.toml / wrangler.json / package.json。 Pages 项目的仓库里绝不能有这些文件
两条从第一站总结的教训

1. 遇到界面字段找不到，优先在项目内解决（加文件、改脚本），不要在配置文件上做文章—— 第一站为了解决"找不到字段"去加配置文件，结果引入了更严重的问题。

2. 构建成功 ≠ 部署成功。日志里 Success: Build command completed 只是第一步， 真正的失败可能在后面的 deploy 阶段。读日志要从下往上看最终状态。
