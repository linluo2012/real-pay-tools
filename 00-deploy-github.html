GitHub 新建仓库并推送第二站

Real Pay Tools · career.linwt.top · 全程约 5 分钟，只需做一次

关于认证方式 你这台 Mac 上已经存在 SSH 密钥（~/.ssh/id_ed25519.pub），所以本手册走 SSH 方式。 配好之后以后每次推送都不用再输密码或令牌，比 HTTPS + 令牌省事得多。

第 0 步 · 先把 SSH 公钥登记到 GitHub

如果你以前已经在 GitHub 配过这台电脑，可以跳过这一步，直接看第 1 步。

1
打开终端（Terminal），粘贴执行下面这条命令，它会把公钥复制到剪贴板：
cat ~/.ssh/id_ed25519.pub | pbcopy
2
浏览器打开 github.com 并登录 → 点右上角头像 → Settings。
3
左侧菜单点 SSH and GPG keys → 右上角绿色按钮 New SSH key。
4
Title 随便填（如 Mac）；Key type 保持 Authentication Key； 在 Key 那个大文本框里按 ⌘+V 粘贴。
5
点 Add SSH key。（可能会要求输入一次 GitHub 密码确认）
6
回终端验证是否连通：
ssh -T git@github.com
第一次会问 Are you sure you want to continue connecting (yes/no)?，输入 yes 回车。 看到 Hi 你的用户名! You've successfully authenticated... 就成功了。

第 1 步 · 新建空仓库

1

2
按下面这张表填：

选成 Private 了怎么办？

不影响本次推送。只要你是仓库所有者，认证通过后 public 和 private 一样能推。

但私有仓库会让后面的 Cloudflare Pages 多一步：在 Cloudflare 里默认搜不到私有仓库， 得先点「去 GitHub 上为 Cloudflare Pages 应用配置仓库访问权限」，在 GitHub 的 Repository access 里单独把这个仓库勾上，再回 Cloudflare 刷新才能看到。

另外，本站是纯静态 HTML/CSS/JS，不含任何密钥或后端，代码保密意义不大 （网页右键「查看源代码」本来就能看到）。所以建议改成 Public，省掉后面那步麻烦。

改
把已有仓库改成 Public：进入仓库页面 → Settings（右上角 tab） → 左侧最下面 Danger Zone → Change visibility → Change to public → 按提示输入仓库名确认。
（不想改也行，保持 Private 完全可以，只是 Cloudflare 那步要多授权一次，手册后面有说明）
⚠️ 这一步千万别勾错 往下有个「Initialize this repository with」区域，里面三个选项 —— Add a README file、Add .gitignore、Choose a license —— 全部保持不勾选。

原因：你本地已经是一个有提交记录的仓库了。如果 GitHub 这边也生成一个 README， 两边历史就对不上，推送会被拒绝，还得额外处理冲突。空仓库最省事。
3
点绿色按钮 Create repository。

第 2 步 · 复制仓库地址（要 SSH 那个）

创建完成后会跳转到一个写着「Quick setup」的页面。

1
页面中间有一排切换按钮：HTTPS / SSH / GitHub CLI。 点 SSH（默认显示的是 HTTPS，一定要切过来）。
2
复制显示的那个地址，长这样：
git@github.com:你的用户名/real-pay-tools.git
把里面的「你的用户名」换成页面上实际显示的（就是你 GitHub 用户名）。
顺手可以做的 同一个页面往下滚动，会看到一段标题是「…or push an existing repository from the command line」的命令。 那三条命令跟下面第 3 步是同一件事，直接复制粘贴也行。

第 3 步 · 在本地执行推送

把下面命令里的地址换成你刚复制的那个，在终端逐条执行：

# 1. 进入第二站目录 cd /Volumes/2t/workplace/网站副业2 # 2. 关联远程仓库（地址换成你自己的） git remote add origin git@github.com:你的用户名/real-pay-tools.git # 3. 确保当前分支叫 main git branch -M main # 4. 推送 git push -u origin main

正常的话会看到类似这样的输出：

✓
回到 GitHub 刷新页面，能看到 12 个源文件和 build.py 等文件，就是成功了。

出问题了？对照这里

⚠️ 如果看到 Permission denied (publickey)，先这样定位 先跑这条命令，看客户端到底有没有把密钥发出去：
ssh -Tv git@github.com 2>&1 | grep -iE "offering|authenticat|denied"
  • 如果出现 Offering public key: ... — 说明本地密钥没问题，问题在 GitHub 那边没登记这个公钥，回到第 0 步加一次
  • 如果出现 agent contains no identities 且没有 Offering — 说明 ssh-agent 没加载密钥，执行 ssh-add --apple-use-keychain ~/.ssh/id_ed25519
  • 两者都没有 — 密钥文件不存在或权限不对
报错信息原因与解决办法
Permission denied (publickey) 绝大多数情况：公钥没加到 GitHub。

备选方案：改用 HTTPS + 个人令牌（SSH 实在配不通时用）

1
GitHub → 头像 → Settings → 左侧最下面 Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)
2
Note 填 Real Pay Tools，勾上 repo（第一个大项）就够了，拉到最下面点 Generate token
3
立刻复制那个 ghp_ 开头的字符串（关掉页面就再也看不到了）
4
建仓库时第 2 步改成复制 HTTPS 地址（https://github.com/用户名/real-pay-tools.git），然后执行：
cd /Volumes/2t/workplace/网站副业2 git remote add origin https://github.com/用户名/real-pay-tools.git git branch -M main git push -u origin main
用户名填 GitHub 用户名，密码那一栏粘贴 ghp_ 开头的令牌（不是登录密码）。macOS 钥匙串会自动记住，以后不用重复输。
